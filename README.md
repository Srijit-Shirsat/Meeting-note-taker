# Meeting Note Taker Agent

---

## Project Overview

A web application that allows users to upload meeting recordings (audio files) and automatically extracts structured notes, action items, key discussion points, and attendee summaries using AI. The system processes audio files through LangChain with LLM to generate comprehensive meeting summaries, making it easy to capture and organize meeting insights without manual note-taking.

### Target Users

- Professionals who attend frequent meetings and need quick summaries
- Teams that want to track action items and decisions from meetings
- Students who record lectures and need organized notes
- Project managers who need to extract key points from team meetings

### Core Value Proposition

Automatically transform audio meeting recordings into structured, actionable notes with minimal effort. Users can quickly identify what was discussed, what decisions were made, and what action items need to be completed, saving hours of manual note-taking and review time.

## API Endpoints

### Authentication
Authentication is handled entirely by Firebase SDK on the frontend. No backend auth endpoints are required.

### Meeting Endpoints

| Method | Endpoint                  | Protected | Purpose                                       | LLM Integration |
| ------ | ------------------------- | --------- | --------------------------------------------- | --------------- |
| POST   | /api/meetings             | Yes       | Upload new meeting audio file                 | Yes             |
| GET    | /api/meetings             | Yes       | Get all user meetings                         | No              |
| GET    | /api/meetings/:id         | Yes       | Get single meeting with full details          | No              |
| DELETE | /api/meetings/:id         | Yes       | Delete meeting                                | No              |
| POST   | /api/meetings/:id/process | Yes       | Process meeting audio (if not auto-processed) | Yes             |
| GET    | /api/meetings/:id/export  | Yes       | Export meeting as PDF or markdown             | No              |
| GET    | /api/search               | Yes       | Search meetings by title, summary, or date    | No              |

**Date Field:** The `date` field in meetings is automatically generated by the backend using `datetime.now().strftime("%Y-%m-%d")` when a file is uploaded. The date is stored as a TEXT field in "YYYY-MM-DD" format (e.g., "2024-01-15"). No date input is required from the user during upload.

## Database Schema

### Tables

**meetings**
- Purpose: Store meeting metadata and processing results
- Essential fields: identifier, user reference, file path, title, date (TEXT, format: "YYYY-MM-DD", auto-generated on upload), transcription, summary, timestamps
- Note: The `date` field is automatically set by the backend using `datetime.now().strftime("%Y-%m-%d")` when the audio file is uploaded. No user input is required for the date field.

**action_items**
- Purpose: Store action items extracted from meetings
- Essential fields: identifier, meeting reference, description, assignee (if mentioned), status
- Relationships: belongs to meeting

**decisions**
- Purpose: Store decisions made during meetings
- Essential fields: identifier, meeting reference, decision text
- Relationships: belongs to meeting

**discussion_points**
- Purpose: Store key discussion points from meetings
- Essential fields: identifier, meeting reference, point text
- Relationships: belongs to meeting

### Relationships
- User → Meetings: One-to-many (via user reference in meetings table)
- Meetings → Action Items: One-to-many
- Meetings → Decisions: One-to-many
- Meetings → Discussion Points: One-to-man

# Backend - FastAPI Application

FastAPI backend with Google Gemini LLM integration.

## Quick Start

1. Install UV (if not already installed):

   ```bash
   pip install uv
   ```

2. Create virtual environment:

   ```bash
   uv venv
   ```

3. Activate virtual environment:

   **On Windows:**
   ```bash
   .venv\Scripts\activate
   ```

   **On macOS/Linux:**
   ```bash
   source .venv/bin/activate
   ```

4. Install dependencies:

   ```bash
   uv add -r requirements.txt
   ```

5. Create a `.env` file with your Google API key:

   ```
   GOOGLE_API_KEY=your_api_key_here
   ```

6. Run the server:
   ```bash
   uvicorn main:app --reload
   ```

The server will start at http://localhost:8000
